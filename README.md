**iShop — вторая концепция**

Отдельная версия после UX-аудита. Первая версия не изменена.

Главная стала короче до товарной сетки, поиск доступен в шапке, на телефоне сохранена нижняя навигация. Добавлены фильтры, русский поиск, избранное, сравнение, страницы выбора комплектации, корректные фото вариантов в корзине, восстановление удаления, проверка данных и двухшаговое оформление. Есть информационные страницы и руководства. Светлая/тёмная темы, мягкое сияние кнопок, свайпы и фоновая анимация сохранены.

**Предпросмотр**

Все файлы сайта находятся здесь. Для GitHub Pages загрузите содержимое этой папки в корень отдельного репозитория, затем в Settings → Pages выберите публикацию ветки main из /(root). Файл index.html должен лежать в корне выбранного источника.

Локальный запуск: `node tools/serve.cjs`, затем откройте http://127.0.0.1:4182. Нужен Node.js 22 или новее. Сайт не требует установки npm-пакетов.

**Что необходимо подтвердить перед реальными продажами**

Это предпросмотр: исходный демонстрационный ассортимент сохранён. Цены базовых версий ориентировочные, остатки не подключены. Другие варианты показывают цену по запросу; прежняя формула +10 000 ₽ удалена. Неподтверждённые контакты, сроки, гарантии и отзывы не выдуманы.

В `store-config.js` укажите город, адрес, часы, реквизиты, контакты, условия доставки/оплаты/гарантии, ссылку на политику обработки данных и адрес сайта. В `products.js` проверьте каждую характеристику и модель. В `core.js` функции options/variant описывают демонстрационные конфигурации: перед продажами замените их реальной таблицей SKU, цен и остатков, включая SIM/регион, ОЗУ и память. Проверяйте совместимость аксессуаров по точным моделям.

Пока `demo: true`, отправка не происходит, а финальный экран явно говорит, что подборка не отправлена. Персональные данные формы находятся только в памяти вкладки. Корзина и избранное хранятся локально под отдельными ключами второй версии.

**Подключение заявок**

Укажите `orderEndpoint` (HTTPS), `privacyUrl` и установите `demo: false` только после подготовки реального приёма заявок. Endpoint получает POST JSON:

```json
{"customer":{"name":"…","phone":"…","city":"…","delivery":"pickup","address":"","comment":""},"items":[{"id":"…","memory":"…","color":"…","sim":"…","ram":"…","qty":1}],"consent":true,"requestId":"uuid"}
```

Успешный серверный ответ: HTTP 200/201 и `{"orderId":"реальный номер"}`. Только после этого интерфейс показывает «Заявка принята». Отказ, тайм-аут или ответ без номера не считаются успешной отправкой.

Сервер должен валидировать поля и SKU, рассчитывать цены по собственной базе, проверять остатки, сохранять заявку надёжно, защищать endpoint от спама и обрабатывать requestId идемпотентно. Настройте CORS для точного домена магазина. Токены Telegram/CRM размещайте только на сервере. Эта поставка не включает размещённый сервер, обработчика персональных данных или онлайн-оплату.

**Сборка и проверка**

После изменения контента: `node tools/build.cjs`. Все HTML-страницы предварительно содержат текст и товары, в том числе без JavaScript. У каждого устройства отдельный адрес. В режиме предпросмотра включён noindex; после настройки siteUrl и выхода из demo сборщик добавляет canonical и sitemap. Структурированные предложения с ценами следует подключать только к подтверждённому ассортименту.

`node tests/core.test.cjs` — проверка поиска, вариантов, фильтров, корзины и формы. Перед включением продаж обязательны сквозная проверка endpoint, фактическое получение заявки магазином, проверка обоих мобильных браузеров и актуальности условий.

Практические следующие подключения: реальные фотографии/отзывы и адрес магазина, остатки, совместимые аксессуары, аналитика воронки. Trade-in, сервис и лояльность стоит добавлять после подтверждения процессов бизнеса.
